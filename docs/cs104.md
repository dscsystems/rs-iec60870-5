# `cs104` — IEC 60870-5-104 over TCP/IP

The `cs104` module implements the IEC 60870-5-104 transport (APCI) with the
full state machine: I/S/U frames, the k and w flow-control windows, the t₀–t₃
timers, StartDT/StopDT activation and TestFR keep-alive.

| Type | Role |
|------|------|
| [`Client`] | controlling station (master): connects to an outstation |
| [`Server`] | controlled station (outstation): listens for masters |
| [`ServerSpecial`] | controlled station that dials out to the master, for NAT traversal |
| [`Connection`] | the handle to one live connection, handed to handlers and callbacks |

Default port `PORT` (2404), or `PORT_SECURE` (19998) with TLS. Default ASDU
parameters `PARAMS_WIDE` — cause of transmission 2 with originator address,
common address 2, information object address 3 — the IEC 104 standard layout.

## Controlled station

```rust,no_run
use rs_iec60870_5::asdu::*;
use rs_iec60870_5::cs104::{Server, ServerHandler};

struct Outstation;

#[async_trait::async_trait]
impl ServerHandler for Outstation {
    async fn interrogation(
        &self,
        c: &dyn Connect,
        pack: &Asdu,
        qoi: QualifierOfInterrogation,
    ) -> rs_iec60870_5::Result<()> {
        if qoi != QualifierOfInterrogation::STATION {
            return c.send(pack.reply_mirror(Cause::ACTIVATION_CON).negated()).await;
        }
        c.send(pack.reply_mirror(Cause::ACTIVATION_CON)).await?;

        let coa = CauseOfTransmission::new(Cause::INTERROGATED_BY_STATION);
        c.send_single(false, coa, pack.common_addr(), &[SinglePointInfo::new(100, true)]).await?;

        c.send(pack.reply_mirror(Cause::ACTIVATION_TERM)).await
    }

    async fn asdu(&self, c: &dyn Connect, pack: &Asdu) -> rs_iec60870_5::Result<()> {
        if pack.type_id() == TypeId::C_SC_NA_1 {
            let cmd = pack.get_single_cmd()?;
            let _ = cmd;
            c.send(pack.reply_mirror(Cause::ACTIVATION_CON)).await?;
            return c.send(pack.reply_mirror(Cause::ACTIVATION_TERM)).await;
        }
        Err(rs_iec60870_5::Error::TypeIdentifier)   // -> UnknownTypeID mirror
    }
}

# #[tokio::main]
# async fn main() -> rs_iec60870_5::Result<()> {
let srv = Server::new(Outstation);
srv.listen_and_serve("0.0.0.0:2404").await
# }
```

### Configuration

The builders consume and return the `Arc`, so they chain, and must run before
serving:

```rust,no_run
# use std::time::Duration;
# use rs_iec60870_5::asdu::{PARAMS_WIDE, TimeZone};
# use rs_iec60870_5::cs104::{Config, Server, ServerHandler};
# struct H; impl ServerHandler for H {}
let srv = Server::new(H)
    .with_config(Config { send_unack_limit_k: 12, ..Default::default() })
    .with_params(PARAMS_WIDE)          // must match every master
    .with_time_zone(TimeZone::Utc)     // for CP24/CP56 tags
    .with_server_number(0);            // reported to asdu_all
```

An invalid `Config` or `Params` falls back to the defaults rather than failing.
With the `tls` feature, `.with_tls(TlsServerConfig::new(config))` serves TLS.

### Serving

`listen_and_serve(addr)` binds and blocks until [`Server::close`] is called or
the listener fails. `serve(listener)` takes an already bound `TcpListener`,
which is what a caller needs after binding port 0:

```rust,no_run
# use std::sync::Arc;
# use rs_iec60870_5::cs104::{Server, ServerHandler};
# use tokio::net::TcpListener;
# struct H; impl ServerHandler for H {}
# async fn f() -> rs_iec60870_5::Result<()> {
let listener = TcpListener::bind("127.0.0.1:0").await?;
let addr = listener.local_addr()?;          // the port actually bound
let srv = Server::new(H);
tokio::spawn({ let srv = Arc::clone(&srv); async move { srv.serve(listener).await } });
# let _ = addr;
# Ok(())
# }
```

Any number of masters may connect at once; `session_count()` reports how many.

### Publishing data

`Server` implements [`Connect`], and its `send` **broadcasts a copy to every
started session**. That is how spontaneous data is published:

```rust,no_run
# use rs_iec60870_5::asdu::*;
# use rs_iec60870_5::cs104::{Server, ServerHandler};
# struct H; impl ServerHandler for H {}
# async fn f() -> rs_iec60870_5::Result<()> {
# let srv = Server::new(H);
srv.send_single_cp56time2a(
    CauseOfTransmission::new(Cause::SPONTANEOUS),
    1,
    &[SinglePointInfo { ioa: 100, value: true, time: Some(chrono::Utc::now()), ..Default::default() }],
)
.await
# }
```

Only sessions in data transfer — STARTDT confirmed — receive the broadcast,
and each **redundancy group** receives it once (IEC 60870-5-104, clause 10). A
redundancy group is a set of connections to the outstation of which exactly one
is in data transfer; the others stand by, stopped, exchanging only test frames,
until the control side switches over by starting one of them.

| `ServerMode` | Groups |
|--------------|--------|
| `ConnectionIsRedundancyGroup` (default) | every connection is its own group: each master in data transfer gets every broadcast |
| `SingleRedundancyGroup` | all connections are one group: a main and its standbys |
| `MultipleRedundancyGroups(groups)` | connections join a group by the master's IP address; a group with no address takes every master the others do not name, and a master no group takes is refused |

```rust,no_run
# use std::net::IpAddr;
# use rs_iec60870_5::cs104::{RedundancyGroup, Server, ServerHandler, ServerMode};
# struct H; impl ServerHandler for H {}
let srv = Server::new(H)
    .with_mode(ServerMode::MultipleRedundancyGroups(vec![
        RedundancyGroup::new("control centre")
            .with_client("10.0.0.1".parse::<IpAddr>().unwrap())
            .with_client("10.0.0.2".parse::<IpAddr>().unwrap()),
        RedundancyGroup::new("maintenance"),
    ]))
    .with_event_buffer(1000)
    .with_max_connections(4);
```

Starting a connection takes any other connection of its group out of data
transfer: that one is sent nothing more, and an I-frame from its master — which
was not asked and may still believe it is started — closes it.

`with_event_buffer(n)` keeps up to `n` ASDUs per group while none of its
connections is in data transfer, and replays them, oldest first, to the next
one that starts. In the fixed modes the buffer exists even while no master is
connected, so events raised during an outage of the control centre are
delivered when it returns. A full buffer refuses further data rather than
overwriting what it holds, and `send` reports it. `buffered_count()` shows how
much is waiting. The default, zero, keeps nothing: a broadcast with no
connection in data transfer then returns `NotActive`, since the data went
nowhere.

`with_max_connections(n)` refuses connections beyond `n` open at once;
unlimited by default.

Inside a handler, the `&dyn Connect` argument is the **single session** the
request came from, so replies go only to that master.

### `ServerHandler`

Every method has a default that does nothing, so implement only what you need.

| Method | Called for |
|--------|-----------|
| `interrogation(conn, pack, qoi)` | `C_IC_NA_1` |
| `counter_interrogation(conn, pack, qcc)` | `C_CI_NA_1` |
| `read(conn, pack, ioa)` | `C_RD_NA_1` |
| `clock_sync(conn, pack, time)` | `C_CS_NA_1` |
| `reset_process(conn, pack, qrp)` | `C_RP_NA_1` |
| `delay_acquisition(conn, pack, msec)` | `C_CD_NA_1` |
| `asdu(conn, pack)` | everything else, **including all control and parameter commands** |
| `asdu_all(conn, pack, server_number)` | every inbound ASDU, before routing |
| `on_connect(conn)` / `on_connection_lost(conn)` | a master arrived or left |

Dispatch rules:

* The session **pre-validates** the cause of transmission, the common address
  and the information object address of the dedicated types, and answers
  `UnknownCOT` / `UnknownCA` / `UnknownIOA` mirrors on violations. Your handler
  only sees well-formed requests.
* `C_TS_NA_1` (test command) is confirmed automatically with `ActivationCon`.
* If `asdu` returns an error, the session replies with an `UnknownTypeID`
  mirror. Return `Ok(())` for a type you deliberately ignore.
* `asdu_all` runs first for every ASDU; its error is logged and does not stop
  the dispatch.

## Master

```rust,no_run
use rs_iec60870_5::asdu::*;
use rs_iec60870_5::cs104::{Client, ClientHandler, ClientOption};

struct Master;

#[async_trait::async_trait]
impl ClientHandler for Master {
    // Process data lands here, including interrogation responses.
    async fn asdu(&self, _c: &dyn Connect, pack: &Asdu) -> rs_iec60870_5::Result<()> {
        if let TypeId::M_ME_NC_1 | TypeId::M_ME_TF_1 = pack.type_id() {
            for m in pack.get_measured_value_float()? {
                println!("ioa={} value={}", m.ioa, m.value);
            }
        }
        Ok(())
    }
}

# #[tokio::main]
# async fn main() -> rs_iec60870_5::Result<()> {
let client = Client::new(Master, ClientOption::new().with_server("127.0.0.1:2404")?);
client.start()?;
client.wait_active().await;

client
    .interrogation_cmd(CauseOfTransmission::new(Cause::ACTIVATION), 1, QualifierOfInterrogation::STATION)
    .await
# }
```

### `ClientOption`

```rust,no_run
# use std::time::Duration;
# use rs_iec60870_5::asdu::PARAMS_WIDE;
# use rs_iec60870_5::cs104::{ClientOption, Config};
# fn f() -> rs_iec60870_5::Result<()> {
let option = ClientOption::new()
    .with_server("127.0.0.1:2404")?     // host:port, :port, or tcp:// tls:// ssl:// tcps://
    .with_config(Config::default())
    .with_params(PARAMS_WIDE)
    .with_auto_reconnect(true)          // default
    .with_reconnect_interval(Duration::from_secs(60))
    .with_auto_start_dt(true)           // default
    .with_client_number(0);             // reported to the handler in ClientContext
# Ok(())
# }
```

A leading `:` means loopback, so `":2404"` is `127.0.0.1:2404`. The TLS schemes
require the `tls` feature and `.with_tls(...)`.

### Activation

A 104 connection begins in **STOPDT**: the outstation discards I-frames and
[`Client::send`] returns [`Error::NotActive`] until `STARTDT` is confirmed.
`with_auto_start_dt` is on by default, so the client activates itself. Turn it
off to drive activation by hand with `send_start_dt()` / `send_stop_dt()`, or
[`Connection::send_start_dt`] on the connection handle.

`wait_active()` resolves as soon as the link activates, and returns immediately
if it already has. It does **not** resolve if the connection drops, so pair it
with `tokio::time::timeout` when the wait must be bounded. `is_active()` and
`is_connected()` report the current state.

### Requests

`Client` implements [`Connect`], so every [`ConnectExt`] helper works against
it. It also has short wrappers for the system commands:

```rust,no_run
# use rs_iec60870_5::asdu::*;
# use rs_iec60870_5::cs104::{Client, ClientHandler};
# struct H; impl ClientHandler for H {}
# async fn f(client: &Client<H>) -> rs_iec60870_5::Result<()> {
# let (coa, ca) = (CauseOfTransmission::new(Cause::ACTIVATION), 1);
client.interrogation_cmd(coa, ca, QualifierOfInterrogation::STATION).await?;
client.counter_interrogation_cmd(coa, ca, QualifierCountCall::default()).await?;
client.read_cmd(coa, ca, 400).await?;
client.clock_synchronization_cmd(coa, ca, chrono::Utc::now()).await?;
client.reset_process_cmd(coa, ca, QualifierOfResetProcessCmd::GENERAL_RESET).await?;
client.delay_acquire_command(coa, ca, 2500).await?;
client.test_command(coa, ca).await?;

// Control commands go through ConnectExt.
client.send_single_cmd(TypeId::C_SC_NA_1, coa, ca,
    SingleCommandInfo { ioa: 6000, value: true, ..Default::default() }).await
# }
```

### `ClientHandler`

**Note the routing.** The dedicated methods receive the *mirrored command
confirmations* — the echoed `C_*` ASDUs with `ActivationCon` or
`ActivationTerm`. The actual process data (`M_SP`, `M_ME`, `M_IT`, …),
**including interrogation responses**, arrives at `asdu`.

| Method | Called for |
|--------|-----------|
| `interrogation(conn, pack)` | `C_IC_NA_1` confirmations |
| `counter_interrogation(conn, pack)` | `C_CI_NA_1` confirmations |
| `read(conn, pack)` | `C_RD_NA_1` confirmations |
| `test_command(conn, pack)` | `C_TS_NA_1` confirmations |
| `clock_sync(conn, pack)` | `C_CS_NA_1` confirmations |
| `reset_process(conn, pack)` | `C_RP_NA_1` confirmations |
| `delay_acquisition(conn, pack)` | `C_CD_NA_1` confirmations |
| `asdu(conn, pack)` | all process data, and control-command confirmations |
| `asdu_all(conn, pack, ctx)` | every inbound ASDU, before routing |
| `on_connect` / `on_activated` / `on_deactivated` / `on_connection_lost` | state changes |

`ClientContext` carries `client_number`, for gateways that multiplex several
masters.

## Reverse connection

`ServerSpecial` is a controlled station that dials out to the master, for an
outstation behind NAT. It answers interrogation and StartDT exactly like a
`Server` session; only the direction of the TCP connection is reversed. The
endpoint comes from a `ClientOption`, since this end initiates:

```rust,no_run
# use rs_iec60870_5::cs104::{ClientOption, ServerHandler, ServerSpecial};
# struct H; impl ServerHandler for H {}
# fn f() -> rs_iec60870_5::Result<()> {
let station = ServerSpecial::new(H, ClientOption::new().with_server("master.example:2404")?);
station.start()?;
# Ok(())
# }
```

`is_connected()` and `is_active()` report the state; `send` goes to the single
master.

## Configuration reference

| Field | IEC | Range | Default | Meaning |
|-------|-----|-------|---------|---------|
| `connect_timeout0` | t₀ | 1–255 s | 30 s | TCP connection establishment timeout |
| `send_unack_limit_k` | k | 1–32767 | 12 | maximum outstanding I-frames; sending stops at k |
| `send_unack_timeout1` | t₁ | 1–255 s | 15 s | acknowledgement timeout; the connection closes when it expires |
| `recv_unack_limit_w` | w | 1–32767 | 8 | acknowledge at the latest after w received I-frames (keep w ≤ ⅔k) |
| `recv_unack_timeout2` | t₂ | 1–255 s | 10 s | maximum delay before sending a supervisory acknowledgement |
| `idle_timeout3` | t₃ | 1 s–48 h | 20 s | time without receiving anything before a TestFR keep-alive; only received frames restart it |

A zero field takes the standard default; `Config::valid()` substitutes and
range-checks. Both peers should use compatible values — the defaults
interoperate with virtually every implementation in the field.

## Behaviour

* Sequence numbers are 15 bit and wrap at 32767; the window bookkeeping handles
  the wraparound.
* An I-frame with an unexpected send sequence number, or an acknowledgement
  outside the window, **closes the connection**, as the standard requires. The
  client's automatic reconnection then recovers.
* Sends are queued and packed into I-frames by the connection task. A full
  queue yields [`Error::BufferFull`] — back off and retry.
* `Server::send` **broadcasts** to every started session and reports what
  happened: `NotActive` when none is started, the session's own error when all
  of them refused the ASDU, and `PartialBroadcast { failed, total }` when only
  some did. A session whose
  queue was full has lost that ASDU, and this is the only way to find out.
* For bulk replies — an interrogation over a large database, a file transfer —
  use `cs104::waiting(conn, timeout)` inside a handler, or `Server::send_wait`
  / `Server::waiting(timeout)` on the server. These wait for buffer room
  instead of dropping the ASDU. Without them a send loop returns `Ok` for every
  call while quietly losing data once the queue fills: the outstation believes
  it answered in full, and the master has holes it cannot detect. Always bound
  the timeout, so a master that has stopped acknowledging cannot block a
  handler for ever.
* An I-frame received while the connection is stopped closes a controlled
  station's connection, since a master may not send one there. A master
  accepts one and numbers it: dropping it would leave its sequence number
  used, and the next I-frame would close the link as out of sequence.
* STOPDT is a handshake (IEC 60870-5-104, subclause 5.3). A master sends no
  more I-frames once it has sent STOPDT act. A controlled station that
  receives it acknowledges the I-frames it has received, stops sending, and
  returns STOPDT con only when its own I-frames have been acknowledged —
  confirming earlier would stop a connection whose data the master may never
  have received.
* Handlers run on the connection's dispatch task, which is separate from the
  protocol machine, so a slow handler delays only that connection's ASDU
  delivery, never its acknowledgements or keep-alives.

## Errors

| Error | Meaning |
|-------|---------|
| `UseClosedConnection` | not connected |
| `NotActive` | connected, but StartDT is not confirmed; on a `Server`, no session is started |
| `BufferFull` | the outbound queue is full |
| `PartialBroadcast { .. }` | a `Server` broadcast reached some sessions but not all |
| `Apci(_)` | the peer sent a control field the standard does not define; the frame is ignored |
| `Config(_)` | the endpoint or timing configuration is unusable |
| `InvalidAddress(_)` | the endpoint string could not be parsed |
