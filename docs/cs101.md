# `cs101` — IEC 60870-5-101 over serial FT1.2

The `cs101` module implements the IEC 60870-5-101 link layer — the FT1.2 frame
format of IEC 60870-5-1 and the transmission procedures of IEC 60870-5-2 — over
a serial port or a TCP stream.

| Type | Role |
|------|------|
| [`Client`] | primary station (master): drives the link and polls |
| [`Server`] | secondary station (outstation): answers polls |

Two transmission procedures:

* **Unbalanced** (the default): one primary polls one or more secondaries on a
  shared line. Only the primary initiates; secondaries answer polls and
  announce pending events with the ACD bit.
* **Balanced** (point to point): both stations may transmit spontaneously, each
  running a primary role for sending and a secondary role for acknowledging.

Default ASDU parameters `PARAMS_STANDARD_101` — cause of transmission 1, common
address 1, information object address 2. Both ends must agree on those and on
`link_addr_size`, `link_address` and `mode`.

> The link address and the ASDU common address are **distinct concepts**. The
> link address identifies the station on the line; the common address
> identifies the station inside the application layer. They are often
> configured equal in the field, but the library keeps them apart.

## Transports

The same link runs over three transports, selected by `Config::transport`:

```rust
use rs_iec60870_5::cs101::{Config, SerialConfig, TcpConfig, TransportType};

// A local serial port. 8E1 is the framing the standard specifies, and the
// default here. Needs the `serial` feature.
let mut cfg = Config::new();
cfg.serial = SerialConfig::new("/dev/ttyUSB0", 9600);
cfg.link_address = 1;

// Dial out to a terminal server.
let mut cfg = Config::new();
cfg.transport = TransportType::TcpClient;
cfg.tcp = TcpConfig { address: "10.0.0.9:2400".into(), ..Default::default() };

// Or listen, serving one connection at a time.
let mut cfg = Config::new();
cfg.transport = TransportType::TcpServer;
cfg.tcp = TcpConfig { address: ":2400".into(), ..Default::default() };
# assert_eq!(cfg.transport_label(), ":2400");
```

`SerialConfig` carries the port name, baud rate, data bits, `StopBits` and
`Parity`, defaulting to 8E1. `TcpConfig` carries the address, an optional
connect timeout (30 s by default) and, with the `tls` feature, TLS
configurations for either direction.

TCP encapsulation is **still 101** — FT1.2 framing with FCB, acknowledgement and
polling, inside a pipe — not IEC 104. Keep t₁ and t₂ generous enough for the
added network latency.

## Primary station

```rust,no_run
use rs_iec60870_5::asdu::*;
use rs_iec60870_5::cs101::{Client, ClientHandler, ClientOption, Config, SerialConfig};

struct Master;

#[async_trait::async_trait]
impl ClientHandler for Master {
    // Interrogation-caused data, and the C_IC confirmations.
    async fn interrogation(&self, _c: &dyn Connect, pack: &Asdu) -> rs_iec60870_5::Result<()> {
        if pack.type_id() == TypeId::M_SP_NA_1 {
            for p in pack.get_single_point()? {
                println!("ioa={} value={}", p.ioa, p.value);
            }
        }
        Ok(())
    }
}

# #[tokio::main]
# async fn main() -> rs_iec60870_5::Result<()> {
let mut cfg = Config::new();
cfg.serial = SerialConfig::new("/dev/ttyUSB0", 9600);
cfg.link_address = 1;

let cli = Client::new(Master, ClientOption::new().with_config(cfg)?);
cli.start()?;
cli.wait_link_active().await;

cli.interrogation_cmd(CauseOfTransmission::new(Cause::ACTIVATION), 1, QualifierOfInterrogation::STATION).await
# }
```

The client runs the link procedure by itself; you do not drive it:

1. Request status of link, then reset of remote link.
2. The link becomes active — `is_link_active()` turns true and
   `on_link_active` fires.
3. Unbalanced: continuous class 2 polling. A set ACD bit in any response
   triggers a class 1 request. Queued user data is interleaved.
4. The frame count bit is tracked **per station across every FCV frame** —
   user data, class 1/2 requests and test link alike — as IEC 60870-5-2
   requires, and a repeated frame carries the same FCB.
5. A frame that goes unanswered is repeated once after t₁ (then t₂); after that
   the station is re-initialized. With a single secondary, or in balanced mode,
   the connection is torn down so automatic reconnection can recover it.

### `ClientOption`

```rust,no_run
# use std::time::Duration;

# let mut cfg = Config::new(); cfg.serial = SerialConfig::new("/dev/ttyUSB0", 9600);
let option = ClientOption::new()
    .with_config(cfg)?                  // rejected if invalid
    .with_params(PARAMS_STANDARD_101)
    .with_auto_reconnect(true)
    .with_reconnect_interval(Duration::from_secs(30))
    .with_client_number(0);
# Ok(())
# }
```

### Multi-drop

Add every station instead of relying on `Config::link_address`:

```rust,no_run
# use rs_iec60870_5::cs101::ClientOption;
# let option = ClientOption::new();
let option = option
    .with_secondary_address(1)
    .with_secondary_address(2)
    .with_secondary_address(3);
```

The client initializes and polls all of them round-robin, keeps FCB and link
state per station, and keeps serving the healthy ones when one dies.
`Connect::send` targets the first configured address; `send_to(asdu, addr)`
targets any of them.

### Sending

`Client` implements [`Connect`], so every [`ConnectExt`] helper works, plus the
system-command wrappers `interrogation_cmd`, `counter_interrogation_cmd`,
`read_cmd`, `clock_synchronization_cmd`, `reset_process_cmd`,
`delay_acquire_command` and `test_command`. Everything is queued and
transmitted as confirmed user data once the target station's link is free and
active.

Manual link-layer actions, executed by the protocol loop when the link is free
and rarely needed: `send_reset_link()`, `send_request_link_status()`,
`send_req_data_class2()`.

### `ClientHandler`

Routing follows the cause of transmission first and the type identification
second:

| Method | Called for |
|--------|-----------|
| `interrogation(conn, pack)` | interrogation-caused `M_*` data, and `C_IC_NA_1` confirmations |
| `counter_interrogation(conn, pack)` | counter-request-caused `M_IT_*`, and `C_CI_NA_1` confirmations |
| `read` / `test_command` / `clock_sync` / `reset_process` / `delay_acquisition` | the matching `C_*` confirmations |
| `asdu(conn, pack, client_number)` | spontaneous data, control-command confirmations, end of initialization |
| `asdu_all(conn, pack, client_number)` | every inbound ASDU, before routing |
| `on_connect(conn)` | the line is alive: the first frame arrived |
| `on_link_active(conn, link_addr)` | a station's link became active |
| `on_connection_lost(conn)` | the transport went down |

## Secondary station

```rust,no_run
use rs_iec60870_5::asdu::*;
use rs_iec60870_5::cs101::{Config, SerialConfig, Server, ServerHandler};

struct Outstation;

#[async_trait::async_trait]
impl ServerHandler for Outstation {
    async fn interrogation(
        &self,
        c: &dyn Connect,
        pack: &Asdu,
        qoi: QualifierOfInterrogation,
    ) -> rs_iec60870_5::Result<()> {
        if qoi != QualifierOfInterrogation::STATION {
            return c.send(pack.reply_mirror(Cause::ACTIVATION_CON).negated()).await;
        }
        // Each of these is buffered and collected by the primary's next polls.
        c.send(pack.reply_mirror(Cause::ACTIVATION_CON)).await?;
        c.send_single(
            false,
            CauseOfTransmission::new(Cause::INTERROGATED_BY_STATION),
            pack.common_addr(),
            &[SinglePointInfo::new(100, true)],
        )
        .await?;
        c.send(pack.reply_mirror(Cause::ACTIVATION_TERM)).await
    }
}

# #[tokio::main]
# async fn main() -> rs_iec60870_5::Result<()> {
let mut cfg = Config::new();
cfg.serial = SerialConfig::new("/dev/ttyUSB1", 9600);
cfg.link_address = 1;

let srv = Server::new(Outstation).with_config(cfg)?;
srv.start()?;
# Ok(())
# }
```

The server answers the link procedure automatically: status, reset, test, and
**FCB duplicate detection** — a repeated request is answered by retransmitting
the previous response without acting on it again, per IEC 60870-5-2 subclass
5.1.2.

### Buffering, not sending

This is the part that differs most from 104. In unbalanced mode the standard
**forbids unsolicited transmission**, so `send` buffers:

* causes `Periodic` and `Background` go to the **class 2** buffer, for cyclic
  data;
* everything else — spontaneous events, interrogation responses,
  confirmations — goes to the **class 1** buffer;
* pending class 1 data is announced with the **ACD bit** on every response,
  which makes a standard master issue a class 1 request;
* an empty poll is answered with "requested data not available" (FC 9);
* a class poll falls back to the other class when the requested one is empty,
  as IEC 60870-5-101 subclass 6.6 permits;
* a full buffer makes `send` return [`Error::SendQueueFull`].

`buffered()` returns the `(class 1, class 2)` depths, which is the quickest way
to see whether the primary is actually collecting.

In balanced mode `send` queues for spontaneous transmission by this station's
own primary role instead.

### Configuration and binding

```rust,no_run
# use std::time::Duration;
# use rs_iec60870_5::asdu::PARAMS_STANDARD_101;
# use rs_iec60870_5::cs101::{Config, Server, ServerHandler};
# struct H; impl ServerHandler for H {}
# fn f() -> rs_iec60870_5::Result<()> {
# let cfg = Config::new();
let srv = Server::new(H)
    .with_config(cfg)?
    .with_params(PARAMS_STANDARD_101)
    .with_reconnect_interval(Duration::from_secs(30))   // TCP transports only
    .with_server_number(0);
# Ok(())
# }
```

With `TransportType::TcpServer` and port 0, `bind().await` binds the listener
without waiting for a peer, so `listen_addr()` is observable before the first
connection — which is how the tests wire two stations together.

### `ServerHandler`

| Method | Called for |
|--------|-----------|
| `interrogation(conn, pack, qoi)` | `C_IC_NA_1` |
| `counter_interrogation(conn, pack, qcc)` | `C_CI_NA_1` |
| `read(conn, pack, ioa)` | `C_RD_NA_1` |
| `clock_sync(conn, pack, time)` | `C_CS_NA_1` |
| `reset_process(conn, pack, qrp)` | `C_RP_NA_1` |
| `delay_acquisition(conn, pack, msec)` | `C_CD_NA_1` |
| `asdu(conn, pack)` | everything else, including control commands |
| `asdu_all(conn, pack, server_number)` | every inbound ASDU, before routing |
| `on_link_active(conn)` / `on_connection_lost(conn)` | state changes |

## Balanced mode

Set `mode = TransmissionMode::Balanced` on **both** stations and give them the
**same** link address. Use `Client` on station A — it sets the DIR bit — and
`Server` on station B.

* Both stations initialize their transmit direction with a reset of the remote
  link, and may then send confirmed user data spontaneously.
* `send` transmits directly on both ends; the class buffers are not used and
  no polling happens.
* Each side acknowledges the peer's frames and performs FCB duplicate
  detection; a response timeout retries once and then re-initializes the
  direction.

## Configuration reference

| Field | Range | Default | Meaning |
|-------|-------|---------|---------|
| `transport` | serial / tcp-client / tcp-server | serial | how FT1.2 frames are carried |
| `serial` | — | 8E1 at 9600 | serial port settings; the name must be set |
| `tcp` | — | — | TCP address, connect timeout, optional TLS |
| `mode` | unbalanced / balanced | unbalanced | transmission procedure |
| `link_address` | fits `link_addr_size` | 1 | this station (server) or the station to poll (client) |
| `link_addr_size` | 1–2 | 1 | link address octets; must match both ends |
| `timeout_response_t1` | 1–255 s | 10 s | response timeout for confirmed frames |
| `timeout_repeat_t2` | 1–255 s, < t₁ | 5 s | timeout after the first repetition |
| `timeout_test_t3` | 1 s–48 h | 20 s | idle time before a test-link keep-alive |
| `timeout_send_link_msg` | 1 ms–10 s | 200 ms | pacing of the poll and transmit scheduler |
| `max_send_queue_size` | > 0 | 100 | outbound queue and class buffer capacity |
| `max_apdu_length` | 1–253 | 253 | maximum ASDU length in one frame |

The FT1.2 variable-length frame is `68 L L 68 | control | link address | ASDU |
checksum | 16`, where `L` counts the control field, the link address and the
ASDU. `L` is one octet, so it runs to 255 and the frame runs to `L + 6` = 261
octets on the wire — confusing the two costs six octets of every frame, which
is enough to refuse the largest frames the standard defines. `max_asdu_len()`
gives the figure for a link address width: 253 octets with a one octet address,
which is what IEC 60870-5-103 quotes.

`timeout_send_link_msg` is effectively the **polling period** of an unbalanced
primary: every tick it either transmits queued data or polls the next station.
Lower it for latency, raise it to reduce traffic on the line.

`Config::valid()` substitutes the default for each zero timing and then
range-checks, including that t₂ is below t₁.

## Frame format

Three frame formats share the line:

```text
single character   E5
fixed length       10 | C | A... | CS | 16
variable length    68 | L | L | 68 | C | A... | ASDU... | CS | 16
```

`C` is the control field, `A` the link address, `L` the count of control +
address + ASDU octets, and `CS` their arithmetic sum truncated to eight bits.
The module exposes [`Frame`], [`ControlField`], `read_frame`, and the `prim_fc`
and `sec_fc` function-code constants, so a test or a bridge can speak FT1.2
directly.

Checksum, length and end-character violations are logged and skipped; the
receiver resynchronises on the next octet and never stops.

## Troubleshooting

| Symptom | Cause |
|---------|-------|
| `unexpected link address` in the log | `link_address` or `link_addr_size` disagree between the ends |
| ASDUs decode as garbage, wrong types or causes | the `asdu::Params` differ between the ends |
| The link never activates | wrong baud rate, parity or wiring; or the secondary is not answering the status request |
| The primary polls but no data arrives | the secondary buffered nothing — check `buffered()` |
| `SendQueueFull` on the secondary | the primary is not polling fast enough, or not at all |

## Errors

| Error | Meaning |
|-------|---------|
| `UseClosedConnection` | the transport is not open |
| `LinkNotActive` | the link procedure has not completed |
| `SendQueueFull` | the outbound queue or class buffer is full |
| `TimeoutT1` | a confirmed frame went unanswered after its repetition |
| `Frame(_)` | a malformed FT1.2 frame |
| `Config(_)` | the configuration is unusable |
